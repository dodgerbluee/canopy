# PLAN08 additive assistant and MCP contract

Add planning:read and planning:write grant scopes and finite registered tools for all planner read/CRUD/lifecycle/action/schedule/refresh/conversion commands. Writes are owner-reviewed proposals except the existing bounded refresh request. Promotion requires plants:write and any supplied real initial purchase additionally requires purchases:write; completing a planting action requires plants:write while preparation/buying does not. Planner scopes require workspace-wide grants, as future ideas do not have owned-plant IDs. Nested actual plant details are withheld without garden:read. Precise period/source-window shapes survive tool projection. Existing review, revision, replay, request/result limits and revocation apply unchanged.

`askPlantingPlanner(question,planIds,year)` is one bounded synchronous Garden-AI request, with 1–20 explicitly selected workspace plans. It never writes. It distinguishes owned garden records, future intents, existing ownership links and estimated budgets. Current validated source facts/projections only; unknown anchors/first harvest remain unknown. Validate short request-local source/plan reference tokens, bounds, current plan revisions/generations/source context before returning cited original facts. No-source response is a deterministic manual-planning explanation. A validated optional note draft identifies its plan and expected revision. Applying opens the ordinary plan editor with the proposed note appended; normal explicit save/revision controls remain the only write. There is no AI schedule/action/purchase/plant command bypass.

Use the configured Garden model and existing protocol transport, consent, timeout and chat usage guard. Existing askGarden retains owned-plant-only context. Count planner/garden questions together when rejecting multiple synchronous AI calls through aliases/fragments. No new AI service or vector store.
