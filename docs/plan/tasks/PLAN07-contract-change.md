# PLAN07 additive garden conversion contract

`addPlantingToGarden` accepts plan/revision, exactly one reviewed `newPlant: CreatePlantInput` or existing plant ID, and optional open planting action ID + actual completedOn. Uses one transaction and existing collection validation/audit/purchase/context behavior through a narrow adapter. Existing plants must be active and belong to this workspace; never mutate them merely by linking. Creating/linking moves an idea/planned plan to IN_PROGRESS, never COMPLETED. Fulfillment is unique per plan forever, including after plant purge. All actual dates/current-context instants must be on/before workspace today/now. Budget, desired count and intended future placement are never copied as actual values automatically.

`completePlantingAction` records a chosen actual day (not future) for an open action. PREPARE/BUY need no plant and never create one. Sowing/transplant/plant-out require a surviving fulfillment and the current actual plant revision; they update its actual planted date and optionally explicitly confirmed actual context via the existing collection transaction rules. `dismissPlantingAction` closes an open action without a completion day or actual plant write. Completion is immutable; general action edit/delete remains open-only. Overall plan completion remains a separate explicit command, blocked by open actions.

Creating and simultaneously completing a planting action uses addPlantingToGarden's single transaction. Acquisition-only conversion supplies no action ID and leaves every future action open. Existing link + later planting goes through completePlantingAction, never a second conversion. Mutation receipts retain resulting actual plant ID only for privacy tombstoning; purge replays RESOURCE_GONE. No extra copy of actual plant details is retained in planning data.
