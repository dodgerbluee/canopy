# UI25 — Purposeful navigation, year, care and AI surfaces

Status: ACCEPTED.

Garden year is its own `/year` route and primary destination; `/calendar/year` redirects so old links survive. The old Month/Year mode switch is removed from both pages. The account dropdown contains only Sign out; theme controls remain in Settings. Phone navigation stays at five items with a dedicated More page carrying all secondary tools, including the AI assistant.

The AI hub at `/insights` exposes the shared grounded garden-chat dialog, plant photo-comparison entry points, pending suggestion review and current model capability status. Chat logic is shared with Year rather than duplicated. It makes no model request just by opening the page.

Care separates actual scheduled work from read-only regional monthly and condition-based guidance, with source modals and plant/rounds links. The empty schedule explains that regional advice does not create a care plan. The local audit found zero profiles/plans/occurrences/notifications; this change does not create guessed schedules.

Journal adds a searchable modal plant picker, including archived plant history and complete pagination, while retaining whole-garden chronology and existing quick logs. Inbox adds review destinations and a useful empty state; opening it never marks a notification read. Related care/journal/inbox/insight mutation IDs use random values available on LAN HTTP.

Executed evidence in `.artifacts/agents/UI25/`: `web-checks.log` has 81 passing tests and a successful production build; tests include complete plant pagination/repeating cursor and garden timezone month boundaries. `browser-report.json` covers five phone/desktop/theme/small-screen scenarios across seven routes, legacy redirect, menu/More reachability, source details, journal scope, explicit garden question/inbox read and settings theme changes; zero final axe violations/page errors/document overflow. Browser data is synthetic. `published.json` and `live-check.json` record local publication. `plan-gates.log` records task/packet/dispatch/boundary checks.

AI connection editing is the explicitly requested follow-on UI26; this release shows capability status only. Existing backend/provider configuration remains running.
