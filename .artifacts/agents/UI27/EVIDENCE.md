# UI27 — Original photo capture dates

Status: ACCEPTED.

User-authorized additive contract clarification: `AttachPhotoInput.preferCaptureDate` defaults false, preserving explicit old USER/EXIF/UPLOAD_FALLBACK inputs. When true and no explicit takenAt is supplied, read capture metadata from the private original; known-offset EXIF wins, naive EXIF may use the supplied IANA timezone, otherwise its timestamp remains unresolved. Missing capture metadata stays UPLOAD_FALLBACK. No file modification time or image modification date is treated as capture.

Root cause: gallery uploads always sent UPLOAD_FALLBACK when the manual date was blank; neither attachment nor processing extracted DateTimeOriginal. Rounds additionally labelled any selected file as owner-captured now. The reported Android original retained EXIF DateTimeOriginal, OffsetTimeOriginal and subseconds: `2026-10-31T05:30:39.83Z`. Android did not strip the timestamp from this upload.

A bounded TIFF reader now extracts only original capture time, original offset and subseconds from the private original (JPEG/HEIF/WebP containers); modification dates and browser lastModified are not capture evidence. Embedded offsets win over device timezone. Naive timestamps use the explicitly supplied IANA timezone; missing/ambiguous/nonexistent timezone instants stay unresolved. An embedded offset does not falsely claim the browser's IANA capture timezone. USER dates remain authoritative. New attachment opt-in preserves existing API semantics. Gallery/recovered uploads and Rounds opt in, Rounds uses the returned date/provenance and no longer counts historical/fallback photos as captures today. Original bytes and derivative metadata stripping are preserved.

Executed evidence: `date-tests.log` validates the reported original timestamp and parser cases; `backend-tests.log` contains passing media/photodate and full real-Docker processor suites. Initial integration assertions exposed test timezone/precision/page-size assumptions; `graphql-final.log` is the corrected full GraphQL suite passing with original-byte resolution, manual precedence, missing metadata, journal projection and historical calendar placement. `queued-media-worker.log` proves HTTP upload → durable queue → matching current media worker → READY display bytes → original capture-time attachment. `web-checks.log` contains 89 passing tests and final production build. `browser-report.json` covers five insecure-origin Android upload/reselect/checksum/receipt regressions using an original EXIF JPEG. `live-photo-browser.json` verifies the actual repaired photo displays Original date / October 31 on the live phone UI. `generation-check.json` reproduces all generated sources without changes; `vet.log` records static checks.

`repaired-photo.json` records the single normal optimistic-revision updatePhoto correction: only reported photo `41226a18-8717-4fd4-957a-ab28738d9180` and its journal projection move from the November 6 upload date to October 31 capture date; creation/upload timestamps remain intact. Other owner-stated dates were not overwritten. `runtime-live.json`, `publish.log` and `live-check.json` document matching API/worker restart, preserved shared storage/AI configuration and all desktop/phone previews updated. No database migration was required.
